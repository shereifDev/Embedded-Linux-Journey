مراجعة سريعة لدورة البناء
Compilation Process Recap

قبل الغوص في التفاصیل الجدیدة، یجب استحضار الأربع المراحل التي یمر بھا أي كود C لیصبح ملفاً تنفیذیاً:

Compilation Pipeline — خط أنابيب البناء
  1. المعالجة المسبقة (Preprocessing): التعامل مع #include و#define وإنتاج ملف .i (مثلاً الأداة المستخدمة cpp أو gcc -E).
  2. الترجمة (Compilation): تحویل الكود النقي إلى لغة التجمیع (Assembly) وإنتاج ملف .s (مثلاً الأداة gcc -S).
  3. التجمیع (Assembly): تحویل أوامر Assembly إلى لغة الآلة (Machine Code) وإنتاج كائن ملف (Object file) بامتداد .o (بصیغة ELF Relocatable).
  4. الربط (Linking): دمج ملفات .o مع بعضها ومع المكتبات (Libraries) لإنتاج الملف التنفیذي النهائي.
2
مفاهيم لغة C: البناء على النطاق (Scope) وعمر المتغير (Lifetime) وتأثيرها
C Language Concepts: Scope, Lifetime & Their Effect on Build

قبل تحویل الكود إلى Assembly، یجب فھم كیف یتم تنظیم المتغیرات بناءً على خصائصھا في لغة C، لأن ھذا سیحدد أین ستوضع في الملف الثنائي (Binary).

📘
ما هي خاصیتا المتغیر في C؟
  • النطاق (Scope): یمكن رؤیة واستخدام المتغیر أین فقط (داخل كل دالة).
  • عمر المتغیر (Lifetime): متى یُخلق المتغیر في الذاكرة ومتى یموت.

ما هي أنواع المتغیرات ومكان وجودھا؟

النوع مثال النطاق (Scope) العمر (Lifetime) المكان في الذاكرة
المتغیرات المحلیة
Local Variables		 int c = 5;
(داخل دالة main)		 محدود بالدالة یُصنع عند استدعاء الدالة ویموت عند انتھائھا Stack
المتغیرات العامة
Global Variables		 int a;
int b = 6;
(خارج أي دالة)		 الملف كامل (File Scope) یمتد طوال فترة عمل البرنامج (Static Lifetime) .data / .bss
المتغیرات المحلیة الثابتة
Static Local Variables		 static int c = 5;
(داخل دالة)		 محدود بالدالة یُمدد لیصبح بطول عمر البرنامج (Static Lifetime)، لا یموت عند انتھاء الدالة بل یحتفظ بقیمتھا للاستدعاء القادم .data / .bss
C — Variable Types
// Local Variable
int main() {
    int c = 5;
}

// Global Variables
int a;
int b = 6;

// Static Local Variable
int main() {
    static int c = 5;
}

لماذا تهمّنا ھذه المفاھیم في البناء؟

یجب أن یحتوي الملف الثنائي (Executable) على تنظیم دقیق لأن الـ Kernel (OS) هو من سینظم الذاكرة من البرنامج، یفرق بین:

  • المتغیرات التي لھا قیمة ابتدائیة (Initialized).
  • المتغیرات التي لیس لھا قیمة (Uninitialized).
  • المتغیرات الثابتة التي لا يمكن تعدیلھا (Constants/Read-Only).
  • الكود نفسھ (Instructions/Functions).
✅
Key Takeaway

نوع المتغیر في لغة C یحدد القسم (Section) الذي سیوضع فیھ داخل ملف الـ ELF.

3
المعيار المقدس: ELF
Executable and Linkable Format — The Sacred Standard

یجب تنظیم الكود (Instructions) والبیانات (Data) داخل الملف الناتج لیمكنكن الـ Kernel من قراءتھ بشكل صحیح وتشغیلھ، وله تخصیص الذاكرة (Memory Management).

📌
Definition — تعریف

ELF: ھو التنسیق القیاسي (Format) لكیفیة تنظیم الكود والبیانات والمعلومات الوصفیة (Metadata) داخل الملفات الثنائیة لأنظمة لینكس.

كیف يتم تنظیم الـ ELF؟ ⚙

ملف الـ ELF مقسم من الداخل إلى "أقسام" (Sections) بناءً على أنواع البیانات التي حللناھا سابقاً:

ELF File Internal Structure — الهيكل الداخلي لملف ELF
  • البرمجي الكود (Instructions): یوضع في قسم .text.
  • البیانات المھیئة (Initialized Data): توضع في قسم .data.
  • البیانات غیر المھیئة (Uninitialized Data): توضع في قسم .bss یحجز مساحة في الملف على القرص (لتوفیر مساحة) وفقط في الرام عند التشغیل.
  • الثوابت (Constants): توضع في قسم .rodata (قراءة فقط).
⚠️
Important — ملاحظة ھامة

المتغیرات المحلیة (Local variables) والذاكرة الدینامیكیة (Dynamic Allocation) لا توجد كبیانات ثابتة داخل الـ ELF على القرص، بل یتم حجزھا عبر الـ Stack والـ Heap أثناء التشغیل فقط.

4
جدول الرموز / .symtab ودور الـ Linker
Symbol Table & The Role of the Linker

ھذا ھو أھم لغز في عملیة البناء.

⚠️
ما هي مشكلة الـ Missing Symbols؟

تخیل برنامجاً یحتوي على main.c یقوم بمناداة دالة techleef() موجودة في ملف آخر.

  1. عندما یقرأ الـ Compiler المترجم main.c، فإنھ یرى نداء techleef() ولكنه لا یرى الكود الخاص بھا.
  2. الـ CPU لا یفھم أسماء الدوال، بل یفھم قفزات لعناوین في الذاكرة (Memory Addresses).
  3. بما أن المترجم لا یملك عنوان techleef()، فإنھ یضع علامة وھمیة (مثل PLT أو Undefined).
  4. الأداة المسؤولة عن الجمع (Assembler) تصنع ملف main.o (وھو ملف ELF).
Symbol Resolution Flow — تدفق حل الرموز
📌
ما هو الـ Symbol Table؟

كل ملف ELF یحتوي على قسم یسمى .symtab وھو أشبھ بسجل حضور یسجل فیھ كل "الرموز" (أسماء الدوال والمتغیرات العامة) الموجودة في الملف.

في ملف main.o نجد الرمز main معرّفاً (Defined) والرمز techleef غیر معرّف (Undefined).

الملف الذي یحتوي على رموز غیر معرّفة (Undefined) لا يمكن تشغیلھ أبداً — الـ CPU لا یمكنھ القفز لعنوان مجھول.

🧠
اللینكر المنقذ — The Linker (ld)

التعریف الشائع الخاطئ: اللینكر یجمع ملفات .o لیصنع ملفاً تنفیذیاً (جواب سطحي).

التعریف الدقیق العمیق: اللینكر ھو الأداة المسؤولة عن البحث عن الرموز المفقودة (Missing/Undefined Symbols) في ملفات .o أخرى أو مكتبات، ثم دمجھا لحلھا (Resolve) لتكوین ملف تنفیذي سلیم خالٍ من الرموز المجھولة.

✅
Key Takeaway

إذا رأیت خطأ من نوع undefined reference to 'X' فاعلم فوراً أنھ خطأ من الـ Linker وینعني فشل في العثور على الكود الحقیقي الخاص بالدالة/الرمز X في الملفات أو المكتبات التي أعطیتھا له.

5
أنواع ملفات الـ ELF
ELF Types

معیار الـ ELF یحدد 4 أنواع للملفات، لكن یھمنا منھا اثنان أساسیان الآن:

للنقل القابل الملف Relocatable File

الامتداد: .o (Object file)

المعنى: "قابل للنقل" یعني أن العناوین داخلھ لم تُثبت بشكل نھائي، ویحتوي عادة على رموز غیر معرّفة (Undefined Symbols).

قابلیة التشغیل: لا يمكن تشغیلھ.

التنفیذي الملف Executable File

الامتداد: عادة بدون امتداد (مثل main)

المعنى: الـ Linker قام بحل جمیع الرموز المفقودة ودمج الأقسام وحدد العناوین الحقیقیة.

قابلیة التشغیل: جاھز للتشغیل مباشرة.

الخاصية Relocatable (.o) Executable
العناوین غیر ثابتة (نسبية) ثابتة (حقیقیة)
الرموز المفقودة قد توجد (Undefined) لا توجد (كلها Resolved)
قابلية التشغیل ✗ ✓
الإنتاج من الـ Assembler من الـ Linker

أدوات الفحص العكسي
Binutils Inspection Commands

كمھندس أنظمة مدمجة، لا يمكنك قراءة ملفات ELF لأنھا ملفات ثنائیة (ستظھر مشوھة كرموز) ببرنامج cat أو nano، نستخدم أدوات مخصصة للتحلیل:

الأمر الأول: file

Terminal
file main.o
file main
📘
الوظیفة:

یقرأ ترویسة الملف (Header) ویخبرك بنوعھ وھندستھ المعماریة (Architecture).

النتيجة لملف .o: ELF 64-bit LSB relocatable

النتيجة للملف التنفیذي: ELF 64-bit LSB executable

الأمر الثاني: readelf

Terminal
readelf -s main.o
📘
الوظیفة:

أداة جداً قویة لقراءة تفاصیل الـ ELF كلھا.

خیار ھامة: خیار -s (أو --syms) یعرض لك جدول الرموز (.symtab) — یمكنك رؤية الرموز المعرّفة والرموز غیر المعرّفة (UND — Undefined).

💡
Tip

یمكنك استخدام readelf -h لعرض الـ ELF Header، وreadelf -S لعرض الأقسام (Section Headers)، وreadelf -l لعرض الـ Program Headers (التي تھم الـ Kernel عند التشغیل).

الثابت الربط مقابل الدینامیكي الربط
Static vs Dynamic Linking

في نھایة الدرس، ظھر سؤال منطقي جداً:

حین بناء البرنامج، قمنا بربط main.o مع techleef.o لإنتاج الملف التنفیذي main، حیث حلّ اللینكر مشكلة techleef بنجاح. ولكن، دالة مثل printf() أو puts() ظلّت كرمز Undefined حتى داخل الملف التنفیذي main! ومع ذلك اشتغل البرنامج بنجاح! كيف؟

یثبت ھذا أن الـ Linking (الربط) یتم على نوعین أو مرحلتین:

الثابت الربط Static Linking

یتم أثناء عملیة الـ Compilation (بواسطة اللینكر ld).

یأخذ الكود المفقود فعلیاً وینسخھ داخل الملف التنفیذي (كما فعلنا مع techleef).

الدینامیكي الربط Dynamic Linking

یتم أثناء تشغیل البرنامج (Runtime).

اللینكر العادي (Static Linker) یترك بعض الرموز (مثل دوال libc) كـ Undefined متعمداً ویترك علامة تخبر النظام أین یجد ھذه الدوال.

عند تشغیل البرنامج، یتدخل برنامج آخر یسمى الـ Loader / Dynamic Linker ویقوم بحل ھذه الرموز بربطھا بالمكتبات المشتركة (Shared Libraries) الموجودة في النظام (مثل libc.so) أثناء التشغیل.

Static vs Dynamic Linking — مقارنة بصرية
المعيار Static Linking Dynamic Linking
وقت الحل أثناء الترجمة (Compile Time) أثناء التشغیل (Runtime)
الأداة المسؤولة اللینكر (ld) اللودر (Loader / Dynamic Linker)
نسخ الكود یُنسخ فعلیاً داخل الملف التنفیذي لا یُنسخ — یبقى مرجعاً خارجیاً
حجم الملف التنفیذي كبیر صغیر
الاعتمادیة مستقل (لا یحتاج مكتبات خارجیة) یحتاج المكتبات المشتركة موجودة على النظام
✅
Key Takeaway

ھناك "اللینكر" یعمل وقت الترجمة لیحل الرموز الثابتة، وھناك "اللودر" أو "اللینكر الدینامیك" یعمل وقت التشغیل لیحل الرموز المرتبطة بمكتبات خارجیة. ھذا الموضوع سیتم تفصیلھ بالكامل في الدرس القادم.

مراجعة سريعة — Quick Review

Main Concepts — المفاهیم الرئيسیة
  • دورة البناء تتكون من أربع مراحل: Preprocessing → Compilation → Assembly → Linking.
  • كل متغیر في لغة C یملك خاصیتین: النطاق (Scope) وعمر المتغیر (Lifetime)، وھاتان الخاصیتان تحددان أین سیوضع المتغیر في الملف الثنائي.
  • معیار ELF ینظم الكود والبیانات داخل أقسام: .text للكود، .data للبیانات المھیئة، .bss للبیانات غیر المھیئة، .rodata للثوابت.
  • جدول الرموز .symtab یسجل كل الدوال والمتغیرات العامة في الملف، ویصنّفھا كـ Defined أو Undefined.
  • اللینكر ھو الأداة المسؤولة عن حل الرموز المفقودة عبر البحث في ملفات .o أخرى والمكتبات ثم دمجھا.
  • ملفات ELF نوعان رئیسیان: Relocatable (غیر قابل للتشغیل) وExecutable (قاھز للتشغیل).
  • الربط نوعان: ثابت (Static) یتم وقت الترجمة، ودینامیكي (Dynamic) یتم وقت التشغیل عبر الـ Loader.
Important Definitions — تعریفات ھامة
  • ELF (Executable and Linkable Format): التنسیق القیاسي لتنظیم الكود والبیانات والمعلومات الوصفیة داخل الملفات الثنائیة لأنظمة لینكس.
  • Symbol Table (.symtab): قسم داخل ملف ELF یسجل أسماء الرموز (الدوال والمتغیرات العامة) وحالتھا (Defined أو Undefined).
  • Relocatable File: ملف كائن (.o) عناوینه غیر ثابتة وقد یحتوي على رموز غیر معرّفة، لا يمكن تشغیلھ.
  • Executable File: ملف تنفیذي عناوینه ثابتة وجمیع رموزه محسومة، جاھز للتشغیل مباشرة.
  • Static Linking: نسخ الكود المفقود فعلیاً داخل الملف التنفیذي أثناء الترجمة.
  • Dynamic Linking: ترك بعض الرموز كـ Undefined وحلھا عند التشغیل عبر الـ Loader والمكتبات المشتركة.
Common Mistakes — الأخطاء الشائعة
  • الخلط بین تعریف اللینكر بأنه "یجمع الملفات فقط" — التعریف الدقیق ھو أنه "یحل الرموز المفقودة ثم یدمج".
  • الاعتقاد أن المتغیرات المحلیة توجد كبیانات في ملف ELF — هی لا توجد على القرص، بل تُحجز في Stack أثناء التشغیل فقط.
  • نسیان أن .bss لا یشغل مساحة على القرص — یحجز مساحة في الرام فقط عند التشغیل.
  • عدم التمیز بین Static Linking (وقت الترجمة) وDynamic Linking (وقت التشغیل).
  • محاولة تشغیل ملف .o مباشرة — ھذا مستحیل لأنه یحتوي على رموز غیر معرّفة وعناوین غیر ثابتة.
Interview Notes — ملاحظات للمقابلات
  • "ما الفرق بین Relocatable وExecutable في ELF؟" — أجب عن العناوین والرموز المفقودة وقابلیة التشغیل.
  • "ما ھو الـ Symbol Table وما فائدتھ؟" — سجل الرموز، یساعد اللینكر في حل الرموز المفقودة.
  • "ما الفرق بین Static وDynamic Linking؟" — وقت الحل، الأداة المسؤولة، حجم الملف، الاعتمادیة على مكتبات خارجیة.
  • "لماذا لا یمكن تشغیل ملف .o؟" — لأنه یحتوي على رموز Undefined وعناوین غیر ثابتة.
  • "ما ھذا الخطأ: undefined reference to 'X'؟" — خطأ من الـ Linker یعنی عدم العثور على تعریف الرمز X.
  • "أین توضع المتغیرات الثابتة المحلیة (static local) في الذاكرة؟" — في .data أو .bss (لیس في Stack) لأن عمرھا Static Lifetime.
Memory Tips — نصائح للحفظ
  • .text = تنفیذي (كود البرنامج) — فكر فیھ كـ "نص" البرنامج الذي یُنفذ.
  • .data = بیانات لھا قیمة — "data" تعني بیانات مھیئة.
  • .bss = "Block Started by Symbol" — بیانات بدون قیمة ابتدائیة، لا مكان لھا على القرص.
  • .rodata = "Read-Only Data" — ثوابت لا تتغیر.
  • اللینكر = المحلل: یحل المشاكل (الرموز المفقودة) ثم یجمع.
  • Static = مبكر: یتم وقت الترجمة (مبكراً). Dynamic = متأخر: یتم وقت التشغیل (متأخراً).
Exam Tips — نصائح للامتحانات
  • توقع سؤالاً عن مطابقة كل نوع متغیر بالقسم (Section) المناسب في ELF.
  • قد یُطلب منك كتابة أمر readelf لعرض الرموز — الجواب: readelf -s file.o.
  • قد یُطلب منك تمییز نوع ملف ELF من نتیجة أمر file — ركز على كلمات relocatable مقابل executable.
  • الفرق بین Static وDynamic Linking من أكثر المواضیع التي تُختبر.
  • توقع سؤالاً عن سبب عدم وجود المتغیرات المحلیة في أقسام ELF.
Revision Checklist — قائمة المراجعة
  • أستطيع ذكر المراحل الأربع لدورة البناء بالترتیب.
  • أعرف الفرق بین النطاق (Scope) وعمر المتغیر (Lifetime).
  • أستطيع تصنیف أي متغیر إلى: محلي، عام، أو ثابت محلي.
  • أعرف أین یوضع كل نوع متغیر في أقسام ELF.
  • أستطيع شرح ما ھو ELF ولماذا ھو ضروري.
  • أعرف وظیفة كل قسم: .text، .data، .bss، .rodata.
  • أفھم ما ھو جدول الرموز .symtab وخیارات عرضھ بـ readelf.
  • أستطیع شرح مشكلة Missing Symbols وكیف یحلھا اللینكر.
  • أعرف الفرق بین Relocatable وExecutable.
  • أستطیع استخدام file وreadelf -s لفحص ملفات ثنائیة.
  • أفهم الفرق بین Static Linking وDynamic Linking.
  • أعرف ما ھو الـ Loader / Dynamic Linker ومتى یعمل.
